# 容器运行时管理（Container Runtime Management）

> 状态: stable
> 最后更新: 2026-11-23
> 反推来源: common/rpc 能力面接口、beacon 容器服务与镜像缓存、beacon-web 容器表单与批量操作

## 设计意图

约束 Server 向 Agent 下发容器运行时（容器、镜像、网络）控制指令时的能力边界、列表口径与结果可见性，保证用户看到的资源状态与实际执行结果一致，且产品不会通过隐式能力扩张获得未声明的系统级控制。

本文件描述长期有效的领域约束：只写必须满足什么、允许什么、禁止什么，以及如何验证；不写实现步骤、临时文件路径、局部命名方案、可替换技术选型或伪代码。若路径本身是稳定协议表面，必须说明其契约身份与验收方式。

## 约束空间

### 不变量（始终成立的断言）

| 编号 | 不变量 | 验收方式 |
|------|--------|----------|
| IC001 | Agent 暴露给 Server 的控制能力必须由单一显式接口枚举定义，并构成可审计的能力面快照；任何新增控制能力必须显式加入该枚举，禁止通过通用转发、反射或动态方法名绕过枚举扩张能力面。 | 对比该接口的方法集合与能力面快照；未修改接口的新增能力不可达。 |
| IC002 | 镜像删除必须先经反向隧道在目标 Agent 上执行，成功返回后才允许使该 Agent 的镜像列表缓存失效；RPC 失败时必须保留原缓存，禁止在失败路径上伪造删除结果。 | 注入 RPC 失败后断言缓存条数不变；成功路径断言同一请求后的列表不再包含该镜像。 |
| IC003 | 容器列表、容器总数与镜像占用数量必须只基于目标 Agent 的最新上报批次计算；已从最新批次消失的历史容器禁止继续出现在列表与计数中。 | 分批上报覆盖「批 A 含 c1/c2、批 B 仅含 c2」后，列表与总数不含 c1。 |
| IC004 | 容器指标必须按批次追加写入以支持趋势查询，禁止以「仅保留最新批次」的方式覆盖历史容器指标。 | 连续上报多批容器指标后，趋势查询能返回跨批次样本。 |
| IC005 | 容器重启策略的取值必须限定在封闭集合内（不重启、始终重启、除非手动停止、失败时重启），集合外取值必须被拒绝，禁止静默回退为默认策略。 | 对集合内取值验证透传到目标节点；对集合外取值断言请求被拒绝且未下发。 |
| IC006 | 受保护容器（`beacon`）的启动、停止、重启与删除必须在服务端被拒绝；界面禁用按钮只是呈现层保护，禁止作为唯一防线。 | 直接调用 API 对受保护容器执行启停与删除，断言返回拒绝且目标节点无变化；批量选择同样不得包含受保护容器。 |
| IC007 | 容器删除必须以目标节点的运行时容器为唯一事实源：运行时删除失败必须返回可定位错误，禁止伪造成功；删除成功后容器自然从下一次上报批次消失。禁止在 Agent 侧维护本地容器记录或以本地记录判定容器存在性。 | 注入运行时删除失败后断言返回错误且无成功提示；成功删除后断言下一批上报的容器列表不再包含该容器。 |

### 规则（允许 / 禁止）

| 编号 | 规则 | 允许/禁止 | 验收方式 |
|------|------|-----------|----------|
| RC001 | 镜像清理只允许删除未被任何容器引用的悬空镜像；被容器引用的镜像禁止出现在清理结果中。 | 允许（悬空）/ 禁止（被引用） | 在存在被引用镜像的节点执行清理，被引用镜像仍存在。 |
| RC002 | 破坏性操作失败时允许保留操作前的本地视图；禁止在失败路径上关闭确认上下文或展示成功状态。 | 允许（保留）/ 禁止（伪造成功） | 注入失败请求后断言视图未刷新、未展示成功提示。 |

## 对外可观测行为

| 场景 | 输入 | 可观测结果 |
|------|------|------------|
| 查询容器/镜像/网络列表 | 目标 Agent 标识 | 返回该 Agent 最新批次内的资源列表与计数，不含已消失的历史条目。 |
| 删除镜像 | 目标 Agent + 镜像标识 | 目标节点执行成功后才反映到列表；执行失败时列表保持原状并返回具体错误。 |
| 提交集合外的重启策略 | 容器配置 | 请求被拒绝，目标节点不产生新容器。 |
| 清理悬空镜像 | 目标 Agent | 仅悬空镜像被移除，被容器引用的镜像保留。 |
| 破坏性操作失败 | 目标 Agent 返回失败 | 返回具体失败原因，确认上下文与本地输入保留，不展示成功。 |

## 输入 / 输出约束

### 输入合法性

- 合法输入：目标 Agent 标识、容器/镜像/网络标识、封闭集合内的重启策略、容器与网络配置参数。
- 非法输入：缺失目标 Agent 的破坏性操作、集合外的重启策略、无法映射到目标资源的标识。
- 处理语义：非法输入必须被拒绝并返回可定位错误；失败不得在目标节点留下部分执行结果。

### 输出约束

- 每条关键不变量或规则必须有稳定编号和验收方式。
- 输出内容必须能被需求、实现计划或测试证据引用。
- 输出不得降低已有 Domain Spec 的约束强度。

## 状态模型

| 状态 | 含义 |
|------|------|
| `resource-synced` | 列表与计数来自目标 Agent 的最新批次，与实际状态一致。 |
| `resource-stale` | 最新批次缺失或上报中断，列表展示的是历史批次。 |
| `operation-executing` | 控制指令已下发，目标 Agent 尚未返回结果。 |
| `operation-succeeded` | 目标 Agent 返回成功，本地视图据此更新。 |
| `operation-failed` | 目标 Agent 返回失败，本地视图保持操作前状态。 |

### 状态迁移

| 起始状态 | 事件 | 目标状态 | 允许/禁止 |
|----------|------|----------|-----------|
| `resource-synced` | 目标 Agent 上报新批次 | `resource-synced` | 允许（自反） |
| `resource-synced` | 上报中断 | `resource-stale` | 允许 |
| `resource-stale` | 新批次到达 | `resource-synced` | 允许 |
| `resource-synced` | 提交集合外的重启策略 | `N/A（请求被拒绝）` | 禁止 |
| `operation-executing` | 目标 Agent 返回成功 | `operation-succeeded` | 允许 |
| `operation-executing` | 目标 Agent 返回失败 | `operation-failed` | 允许 |
| `operation-failed` | 未重试即展示成功 | `operation-succeeded` | 禁止 |

## 错误条件与失败语义

| 错误条件 | 可观测表现 | 是否可恢复 | 是否幂等 |
|----------|------------|------------|----------|
| 缺失目标 Agent 标识 | 返回可定位错误，目标节点无变化 | 是，补齐标识后重试 | 是 |
| 目标 Agent 不可达或 RPC 超时 | 返回不可达/超时错误，本地视图不变 | 是，Agent 恢复后重试 | 视操作而定 |
| 集合外的重启策略 | 返回校验错误，未下发到目标节点 | 是，改为集合内取值 | 是 |
| 镜像删除在目标节点失败 | 返回具体失败原因，镜像列表保持原状 | 视 Docker 状态而定 | 视操作而定 |
| 目标资源不存在 | 返回 not found，视图不伪造成功 | 是，刷新后重选 | 是 |

## 结果约束（非功能性）

| 维度 | 约束 | 验收方式 |
|------|------|----------|
| 可追踪性 | 约束 ID 必须可被需求、实现计划和测试证据回挂 | 引用检查 |
| 确定性 | 相同输入状态必须产生相同的列表口径与操作结果 | 重复执行同一验收场景 |
| 一致性 | 本地视图、目标 Agent 实际状态与返回结果必须一致 | 前后端回归测试 |
| 安全性 | 能力面扩张必须显式可审计，禁止隐式获得系统级控制 | 接口方法集合比对 |
