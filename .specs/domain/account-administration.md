# 账户管理（Account Administration）

> 状态: stable
> 最后更新: 2026-11-02
> 反推来源: account API, authorization policy and Beacon Web account settings

## 设计意图

约束管理员对用户账户执行查询、创建、更新和删除时的目标、权限、持久化结果与用户可见反馈，避免空目标、部分目标或失败请求被展示为成功。

## 约束空间

### 不变量（始终成立的断言）

| 编号 | 不变量 | 验收方式 |
|------|--------|----------|
| IA001 | 用户删除必须携带至少一个格式有效的明确用户 ID；空数组、空元素或无效 ID 不得进入持久化层。 | 用 API schema 测试覆盖空数组、空元素、非法长度和合法 UUID。 |
| IA002 | 用户删除返回成功时，请求指定的用户必须真实存在并已删除，对应的用户-角色授权关系必须同步移除。 | 用 service/repository 测试覆盖存在目标、不存在目标和 Casbin grouping policy 清理。 |
| IA003 | 删除请求失败时，管理界面必须保留确认上下文，不得关闭弹窗、刷新列表或展示成功状态。 | 用删除组件测试注入失败请求并断言弹窗与刷新行为。 |
| IA004 | 浏览器会话 Token 只能通过 HttpOnly、SameSite Cookie 传递，不得出现在响应体、localStorage、sessionStorage 或 WebSocket query；所有状态变更请求必须通过可读 CSRF Cookie 与请求头双提交校验。 | 用登录/刷新/登出、CSRF 中间件、前端 API client 和 WebSocket 鉴权测试验证。 |
| IA005 | 新数据库只能使用部署期提供的强密码创建唯一 bootstrap 管理员，并要求首次登录后修改；禁止创建公开默认密码或额外默认普通用户。历史默认密码账户升级后也必须进入强制改密状态。 | 用空/弱 bootstrap 密码、新库创建和历史密码迁移测试验证。 |
| IA006 | 新密码至少 12 个字符，并包含小写字母、大写字母、数字、符号中的至少三类。 | 用 bootstrap 与密码更新校验测试覆盖长度和字符类别。 |

### 规则（允许 / 禁止）

| 编号 | 规则 | 允许/禁止 | 验收方式 |
|------|------|-----------|----------|
| RA001 | 管理员可删除权限范围内的其他用户，并可在成功后刷新列表。 | 允许 | 用组件请求参数与 service 成功路径测试验证。 |
| RA002 | 删除目标为空、目标不存在或持久化失败时返回可区分错误，禁止返回成功空结果。 | 禁止 | 用输入校验和不存在目标回归测试验证。 |
| RA003 | 删除确认必须对应用户选定的明确目标；只有删除成功后才能通知界面更新结果。 | 允许 | 用 TypeScript 检查和组件测试验证。 |
| RA004 | 强制改密账户只能访问读取自身会话、更新密码和登出所需边界；完成改密后旧会话必须失效并返回登录页。 | 禁止 | 用权限中间件、路由守卫和强制改密页面测试验证。 |

## 状态模型

### 状态定义

| 状态 | 含义 |
|------|------|
| `user-active` | 用户存在且仍具有持久化账户记录。 |
| `delete-pending` | 管理员已确认目标，删除请求正在执行。 |
| `user-deleted` | 用户记录和对应授权关联已移除。 |
| `delete-failed` | 请求被拒绝或执行失败，原用户状态保持可确认。 |

### 状态迁移

| 起始状态 | 事件 | 目标状态 | 允许/禁止 |
|----------|------|----------|-----------|
| `user-active` | 管理员提交合法删除目标 | `delete-pending` | 允许 |
| `delete-pending` | 用户删除与授权清理成功 | `user-deleted` | 允许 |
| `delete-pending` | 校验、查询或持久化失败 | `delete-failed` | 允许 |
| `user-active` | 空目标或无效 ID 被提交 | `user-deleted` | 禁止 |

## 错误条件与失败语义

| 错误条件 | 可观测表现 | 是否可恢复 | 是否幂等 |
|----------|------------|------------|----------|
| 删除目标为空或格式无效 | API 返回 400，前端保留确认弹窗 | 是，修正目标后重试 | 是 |
| 删除目标不存在 | API 返回 not found，前端不伪造成功 | 是，刷新列表后重新选择 | 是 |
| 持久化或授权清理失败 | API 返回服务错误，前端保留上下文 | 视故障而定 | 视失败阶段而定 |

## 结果约束（非功能性）

| 维度 | 约束 | 验收方式 |
|------|------|----------|
| 可追踪性 | 账户删除约束必须能追溯到实现和持久保留的测试证据；Task Spec 可记录实施过程。 | 引用检查与代码评审。 |
| 一致性 | API 成功、数据库状态、授权状态和界面反馈必须一致。 | 前后端回归测试。 |
| 安全性 | 删除操作必须经过现有 JWT 与 Casbin 权限边界。 | 路由和权限测试。 |
